# SourcePilot 独立立项产品叙事

## 1. 需求分析：采购决策缺少统一事实层

SourcePilot 立项于跨境 B2B 采购场景。目标用户是依赖聊天、邮件和表格完成寻源的中小团队。核心问题不是供应商数量不足，而是采购需求、供应商能力和报价信息无法以同一口径进入决策。

典型痛点：

- RFQ 来自自然语言，数量、目标价、认证、交期与定制要求容易缺失或冲突；
- 供应商资料字段不齐，采购人员需要手工判断 MOQ、认证和交期是否满足；
- 报价结构不同，Logo、包装、固定费用与贸易条款难以横向比较；
- 纯模型推荐存在编造事实、忽略硬约束和解释不可追溯的风险；
- 团队难以复盘候选为何入选、为何被过滤，以及下一步要核验什么。

因此，项目要解决的不是“生成一段采购建议”，而是建立从 RFQ 到 Shortlist 的可审计决策链。

## 2. 方案制定：Agent 理解，确定性引擎裁决

产品采用 1+2 Multi-Agent：Procurement Supervisor 负责任务规划与汇总；Sourcing Agent 负责供应商寻源；Quote Agent 负责报价归一与比较。

模型负责：

- 理解自然语言需求；
- 识别缺失信息并追问；
- 在复杂任务中拆分、路由和解释结果。

确定性代码负责：

- RFQ Schema 校验；
- MOQ、价格、认证、交期和定制能力 Hard Gate；
- Effective Unit Cost 复算；
- 仅在合格候选内执行固定权重排序；
- 输出原因码、未知字段和人工确认边界。

这种混合方案把模型擅长的语义理解与规则擅长的稳定裁决分开，避免让自然语言解释覆盖业务事实。

## 3. MVP 边界：验证 Shortlist 是否可用

MVP 只闭环到“形成可供采购人员确认的供应商 Shortlist”，不执行高风险外部动作。

In Scope：

- RFQ 抽取、缺失项与冲突提示；
- 合成供应商库召回和硬约束过滤；
- 报价抽取、标准化和成本复算；
- Qualified Shortlist、Top-3、风险和下一步核验建议；
- 企业采购偏好、会话状态、事件流和工程护栏；
- 合成评测集与离线回归。

Out of Scope：

- 自动发送询价、自动议价、自动定标；
- 合同、付款、下单或其他真实外部写操作；
- 未经授权的平台数据抓取；
- 将缺失运费、税费的数据包装为完整 Landed Cost；
- 用合成指标代替真实客户 ROI。

## 4. 产品开发：先打通确定性主链路

开发顺序围绕风险从高到低展开：

1. 定义 RFQ、Supplier、Quotation 与 Decision Schema；
2. 实现 RFQ Parser 和缺失/冲突检测；
3. 实现 Supplier Retrieval 与 Hard Constraint Engine；
4. 实现报价解析、Effective Unit Cost 与 Ranking；
5. 接入 Supervisor、Sourcing Agent 和 Quote Agent；
6. 增加偏好记忆、事件流、熔断、循环检测和输出护栏；
7. 完成 React 演示 UI、离线评测和 CI。

优先完成规则与数据契约，再接 Agent，可以让模型行为始终受可测试的边界约束。

## 5. 评测集制定：分层定位问题

评测拆为四层，避免只看一个端到端分数：

| 层级 | 数据集 | 主要指标 | 失败含义 |
|---|---|---|---|
| RFQ | 50 条合成任务 | Schema 合法率、字段准确率、关键约束召回 | 需求理解不稳定 |
| 报价 | 35 条混合格式报价 | 字段准确率、成本计算准确率 | 事实抽取或计算错误 |
| 召回 | 30 条寻源任务 | Recall@K、NDCG、Hard Gate 满足率 | 找不到或错误放行候选 |
| 决策 | 10 条合成决策 | Top-3 一致率、Pairwise Agreement | 软排序权重需校准 |

安全门槛优先于排序：Hard Constraint 满足率未达标时，不应通过增加解释文案掩盖问题。

## 6. 产品迭代：从机制正确到真实可用

### V0：离线机制验证

- 合成数据闭环；
- 验证 RFQ、Hard Gate、报价归一和排序可复现；
- 建立安全与边界回归测试。

### V1：采购人员可用性验证

- 5–10 名采购人员使用脱敏任务；
- 记录首版 Shortlist 的接受、调整与拒绝原因；
- 校准字段优先级、追问策略和排序权重。

### V2：私有数据接入

- 在授权范围内接入企业供应商主数据和历史报价；
- 增加字段血缘、权限、审计与版本管理；
- 评估供应商数据刷新和人工复核流程。

### V3：受控协作

- 仅在人工确认后生成或发送询价；
- 所有外部动作保留审批、撤回和审计记录；
- 不以自动化率替代决策质量。

## 7. 北极星指标与指标树

北极星指标：**周有效采购决策数（WQSD）**。

一次有效采购决策需同时满足：

1. RFQ 关键字段经采购人员确认；
2. Shortlist 中候选均有证据且通过 Hard Gate；
3. 风险、未知字段和成本口径清晰；
4. 采购人员完成接受、调整或有理由拒绝。

护栏指标：

- Hard Constraint 违规率；
- 无证据事实率；
- 人工覆盖率及覆盖原因；
- TTQS（Time to Qualified Shortlist）；
- 每个有效决策的模型成本；
- 评测回归通过率。

WQSD 衡量“系统是否帮助用户完成了一个可追溯决策”，而不是单纯衡量对话数、Agent 调用数或自动化率。
